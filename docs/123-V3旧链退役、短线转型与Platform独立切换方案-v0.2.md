# V3旧链退役、短线转型与Platform独立切换方案 v0.2

> 状态：M0—M2已完成；Platform已接管日线；V3 LaunchAgent、外部软链和隐藏运行消费者已解除，物理归档尚未处理
> 适用系统：Yifei Platform、Yifei V3.1.0、Yifei Shortline、Yifei V4
> 冻结日期：2026-08-25

## 1. 三条最高原则

所有设计、代码和运行任务都必须同时服从：

1. **个人系统**：只解决一个人的盘后研究、竞价观察和人工决策，不建设团队工作流、通用研究平台或自动交易平台。
2. **目标是抓到能上涨的股票**：数据、图表、规则和归因必须最终帮助识别后续上涨机会；不能证明有用的复杂能力不进入生产。
3. **遵循第一性原理**：先确认客观事实和真实问题，再增加最小能力；不以模块数量、评分复杂度或叙事完整度代替交易价值。

## 2. 最终系统定位

```text
                         Platform
                  中立行情、映射和数据健康
                     /                \
                    v                  v
          Shortline短线扫描器            V4机会研究系统
          回答“今天盯谁”               回答“未来几天看谁”
          概念题材 + 集合竞价           Setup + Timeline + Outcome
                     \                /
                      v              v
                          人工决策
```

| 系统 | 核心问题 | 时间尺度 | 板块口径 | 输出 |
|---|---|---|---|---|
| Platform | 市场客观发生了什么 | 日线及已验证的必要盘中快照 | 原始行业、概念及PIT映射 | 事实、版本和数据健康 |
| Shortline | 今天短线情绪如何、竞价强度集中在哪、重点盯谁 | 昨日收盘至今日竞价 | 概念题材为主，行业为背景 | 0—3只人工关注对象 |
| V4 | 哪些机会正在形成、如何演化 | Day0—Day45事实窗口 | 90个行业四象限为背景 | 机会事实、结果和研究归因 |
| 人工 | 是否买、怎么买、何时卖 | 实盘 | 综合判断 | 最终交易决定 |

共同边界：

- 不自动交易；
- Shortline概念题材与V4行业板块不混合排名；
- Platform不保存策略、Setup、评分、推荐或应用状态；
- Shortline短线结论不写入V4生产链；
- V4市场状态和四象限不直接修改Discovery、R1—R3、评分或排序；
- 当前生产V3仍是旧多策略陪跑系统，只在Platform解除物理依赖和Shortline接管前临时保留。

## 3. 模块准入纪律

任何新增功能、模块、定时任务或持久化字段，在进入生产前必须写清：

| 必填项 | 要回答的问题 |
|---|---|
| 上游 | 数据或调用从哪里来，是否为PIT，谁负责质量 |
| 消费者 | 哪个真实运行入口或人工界面每天使用它 |
| 触发路径 | 何时、由谁调用，是否新增调度 |
| 输出合同 | 保存什么，不保存什么，版本和去重单位是什么 |
| 失败行为 | 阻塞、降级还是`unknown`，不得伪装成功 |
| 行为约束 | 明确不能修改哪些生产状态或交易输出 |
| 验收证据 | 哪些测试、对账或前瞻数据证明它可用 |
| 退出条件 | 无消费者、无增量价值或数据失真时如何停用 |

硬规则：

- 单元测试、文档引用和一次性脚本不算真实消费者；
- 没有真实消费者的实现只能留在`lab/experimental`；
- 一个事实只保留一个长期Writer和一个权威来源；
- 不新增Finding、Candidate、Validating等研究管理状态机；
- 归因统一经过各系统已冻结的`AttributionEngine`入口；
- 看完结果后不得临时修改正式假设、主要Outcome或通过门槛。

## 4. 当前状态与迁移边界

### 4.1 2026-08-25收盘后的切换状态

```text
2026-08-25既有事实
  → data/shared/market_data.db + platform_state（不可变保留）

2026-08-26起
外部行情源（新浪完整市场；腾讯既有股票池有界兜底）
  → Platform Daily Market Publisher
  → data/shared/market_data.db + platform_state
  → V4 / Shortline
```

因此：

- V4目前不直接读取V3；
- Platform独立Writer代码和合同已完成，不读取V3物理路径；
- 旧Transitional Publisher在新Writer加载时必须卸载，禁止双Writer；
- 首个生产交易日必须核对日期、行数、覆盖率、来源和V4消费成功；
- 首日闸门通过前保留V3本地目录作为只读回滚材料，不再让它写Platform；
- V3短线探针已加载，但截至2026-08-25晚间尚未经历真实竞价运行。

### 4.2 最终数据链

```text
外部行情源
  → Platform Market Updater
  → data/shared/market_data.db
  → data/shared/platform_state
  ├── Yifei Shortline（只读）
  └── V4（只读）
```

终局禁止：

```text
V4 → V3数据库、健康文件或Python模块
Platform生产任务 → V3物理路径
Shortline → 自建第二套长期日线行情真源
```

## 6. V4市场观察合同

### 6.1 全市场观察

Platform首版提供：

- 上涨、下跌、平盘股票数及上涨比例；
- 全市场等权日收益；
- 涨幅不低于3%的股票比例；
- 跌幅不高于-8%的股票比例；
- 站上MA20的股票比例及有效样本数；
- 全市场成交额及相对前20日中位数；
- 沪深300日线、20日收益和10日实现波动；
- 每个字段的`as_of`、样本数、覆盖率、来源版本和质量状态。

V4可以据此生成版本化研究标签：

```text
risk_on / risk_off / transition / unknown
```

消费者仅限Daily Review和Attribution。禁止修改Discovery、Setup、Timeline、Decision、R1—R3、评分或排序。

### 6.2 行业板块战场四象限V0

第一层只编码客观事实：

| 视觉元素 | 固定口径 |
|---|---|
| X轴：交易水位 | 板块过去20个交易日累计收益在90个行业板块中的百分位 |
| Y轴：交易资源变化 | 当日板块成交额占全市场成交额比例，相比前5个有效交易日中位数的变化 |
| 点颜色：相对强弱 | 板块近5日收益相对同期全市场收益，区分强、弱、接近 |
| 点大小：板块规模 | 板块过去20个交易日平均成交额 |
| 外圈：异常交易 | 当日成交额进入自身此前20个有效交易日90%分位数以上 |
| 尾迹 | 最近5个有效交易日的位置变化 |

X轴以百分位50分高低，Y轴以0分资源增加或减少。相对强弱的中性带在实现前冻结并版本化。

第二层文字摘要才做组合解释：

| 客观组合 | 文字摘要 |
|---|---|
| 低水位 + 资源增加 + 相对强 | 轮入观察 |
| 高水位 + 资源增加 + 相对强 | 强势延续 |
| 高水位 + 资源减少 + 相对弱 | 退潮观察 |
| 低水位 + 资源减少 + 相对弱 | 冷却 |
| 价格与资源方向冲突 | `divergent`（分歧） |

未满足完整组合时只展示事实，不强行归类；输入不足显示`unknown`。这些词是展示描述，不是Evidence或交易判断。

四象限上游为Platform行业事实，消费者仅为V4 Daily Review和Attribution。由现有Daily Review/Finalizer触发，不建立独立调度器。

## 7. 推进方式

采用“一条主动实施线 + 一条被动证据时钟”：

- 主动实施线一次只推进一个完整阶段，完成合同、实现、测试、Open Code Review和提交后再进入下一阶段；
- 短线探针按计划自动积累竞价事实，但不推送、不触发归因、不修改生产；
- 探针数据足够时可以做水位审计，但不能插队建设新功能。

## 8. 分阶段实施

### M0：三系统定位和总合同冻结

状态：已完成。

产物：

- 本方案v0.2；
- V3短线强势扫描器定位决议v0.1；
- 权威系统地图中的当前/目标双状态。

验收：只修改文档，不修改代码、调度或生产状态。

### M1：收口当前V3工作区

目标：在新增任何实现前，先让当前生产和实验版本可审计。

工作：

1. 审查Dragon补充、OBS雷达、交付记录和归因改动；
2. 理清上游、消费者、触发和失败行为；
3. 核实`daily_top`为空与`delivery_degraded`的真实因果；
4. 生产改动和实验探针分开测试、分开提交；
5. 停止与“人工主动归因/调参”纪律冲突的`tuning.weekly`；
6. 保持短线探针不推送、不接主链。

验收：

- Open Code Review无阻塞问题；
- 相关测试全部通过；
- 三个仓库的修改归属清楚；
- V3工作区干净；
- 自动归因和自动调参均不运行；
- 探针代码与运行版本可追溯。

### M2：Platform日线事实合同

目标：让共享数据库具备V4市场观察的正式输入。

工作：冻结`index_daily.v1`、`market_breadth_daily.v1`和数据健康合同；迁移已有指数历史；由Transitional Publisher同步指数并计算确定性宽度事实。

消费者：V4 Market Observation和Attribution。

约束：不做竞价、概念、短线扫描器或四象限界面；指数缺失只降低市场观察，不阻断V4核心Discovery。

验收：同一输入重复发布一致，PIT和覆盖率测试通过，V4不读取V3物理路径。

### M3：V4市场观察卡与行业四象限

目标：在人每天复盘的入口保留必要市场背景。

上游：M2正式事实及Platform现有行业事实。

消费者：V4 Daily Review和Attribution。

触发：V4现有Daily Review/Finalizer，不新增调度。

约束：只展示和研究，不影响Decision、状态、评分或排序。

验收：图表、短摘要、版本和质量状态齐全；接入前后V4生产Decision结果完全一致。

### M4：Platform独立日线Updater与切换

目标：移除Platform对V3物理数据路径的长期依赖。

工作：Platform独立抓取个股日线、指数和交易日历，写隔离候选库；与V3桥连续5个交易日对账；人工批准后切换唯一Writer并观察至少2个交易日。

消费者：Shortline和V4只读消费Platform事实。

约束：不能双Writer写生产库；失败必须明确报错，不能复制前一日冒充当日；回滚只允许人工执行。

### M5：短线扫描器数据闸门

目标：只判断竞价和概念数据是否真实可用，不评价策略收益。

最低观察：至少一个完整真实交易日，具备9:16、9:18、9:20、9:25四个快照。必须同时满足覆盖、时效、字段语义和人工抽查合同；如仍有实质疑问则继续采集，不为凑固定天数机械等待。

检查：

- 实际采集时间和数据源时间；
- 请求、返回和可用字段覆盖；
- 价格、成交量、成交额的真实语义；
- 四个时点变化是否可解释；
- 与人工竞价界面抽样核对；
- 概念名称、稳定代码、完整分页成分和PIT保存；
- 数据失败是否明确暴露。

输出只能是：`足以支撑Shortline / 不足以支撑Shortline`。未通过则停止后续短线开发，不用替代字段硬凑。

### M6：Yifei Shortline日常陪跑V1

前提：M5通过。

输入：昨日强势结构、竞价快照、概念题材聚集、必要行业背景和数据健康。

输出：9:20日常陪跑Artifact和一条人工观察预警，包含市场短线情绪、集中题材和0—3只重点股；没有机会明确输出“今日无重点短线机会”。9:25只记录最终竞价，不补发预警。

消费者：用户每日人工查看和统一AttributionEngine。

禁止：自动交易、旧综合评分、旧Lifecycle池、概念行业混排、自动调参和自动归因。陪跑预警对用户可见，但不代表规则已经证明有选股优势。

### M7：自然样本积累与人工归因

陪跑规则开始积累样本后保持版本冻结，不因个别案例调参。由用户主动运行统一AttributionEngine，评估选股后效和开盘后收益空间。

如未来研究模拟交易收益，必须另行冻结成交价格锚点、T+1约束、涨跌停可成交量、佣金、印花税、滑点、对照组和数字化通过标准。

只回答：

1. 9:20能否稳定识别当天集中题材；
2. 0—3只重点股是否优于可交易市场基线；
3. 竞价是否给昨日强势结构带来增量价值。

归因证明没有增量价值时应删除或重新提出新版本，不通过事后增加规则或改阈值抢救。

### M8：经证明有长期价值后迁移中立事实

前提：短线扫描器已自然积累样本，人工归因证明其值得长期保留。该前提只限制中立事实迁移，不阻塞M6日常陪跑。

迁入Platform：竞价原始快照、概念名称、PIT成分、来源时间、覆盖率和健康状态。

留在Shortline：短线情绪解释、题材集中判断、重点股选择和9:20人工预警。

迁移后连续观至少5个交易日；Shortline只读Platform日线事实，不保留第二套长期日线行情真源。

### M9：V3旧多策略链退役与归档

停止：旧多策略EOD主链、Lifecycle池、Family Lane、综合评分、Afterburner、Propagation、旧盘中确认、旧自动调参和无消费者模块。

转交Shortline：9:20人工预警、9:25事实记录和人工归因入口。

V3代码提交和退役Tag推送远端后封存；必要中立数据迁出，无长期消费者的运行产物经清单确认后删除，最终清理本地V3目录。V4继续独立运行。

截至2026-08-26，M9已完成第一部分运行层分离：

- 10个已安装的`com.yplus.v3.*` LaunchAgent均已卸载并移除；
- V2指向V3主数据库的兼容软链已解除；
- 历史备份目录中指向旧桌面V3路径的断链已解除；
- Platform、V4和Shortline的独立生产任务继续保留；
- V3数据库实体、代码仓库和运行产物均未在本步骤删除。

随后已完成隐藏运行消费者分离：Hermes停用V3决策面板和旧市场叙事任务，只保留一个20:15调用V4公开命令的市场认知卡任务；`individual-stock-analysis`改读Platform事实合同，不再读取V3数据库。V4市场认知卡只供人工盘后阅读，不进入Discovery、Decision、评分或排序。物理删除前仍须处置未合并worktree、迁移个人事实、制作并校验退役归档包、核对远端仓库和退役Tag，并通过最终删除闸门。详见`docs/124-V3数据资产退役清单-v0.1.md`。

## 9. 明确不做

- 不新增V4 Detector或调整R1—R3；
- 不建设通用研究平台、综合评分或自动Top1—2；
- 不把Market Regime或四象限变成交易门禁；
- 不把概念和行业混合排名；
- 不构造“主力净流入”、北向替代值或板块间资金迁移因果箭头；
- 不加入新闻情绪、LLM判断或自动参数优化；
- 不因一个漂亮案例宣称短线扫描器有选股优势或临时调参；
- 不在验证数据价值前为短线扫描器扩建Platform。

## 10. 下一步

M0—M2已完成，M9的LaunchAgent、软链和隐藏运行消费者分离已完成，数据清单已形成。下一步在人工确认后迁移个人事实；随后分别制作退役归档包、处置worktree并通过最终删除闸门。M3按原计划推进；Shortline探针按真实竞价时点独立继续采集，不新增影子层。
